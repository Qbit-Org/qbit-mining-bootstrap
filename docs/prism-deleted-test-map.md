# Deleted 2.x.x tests and their 3.x.x replacements

This map lists every test file that exists on `origin/2.x.x` (504846c) and is absent on the 3.x.x base it was built against (8dccc74, the merge of #316), with the 3.x.x test that covers the same behaviour, or the open issue that will. All 142 files were deleted by the native PRISM server cutover (#244). This is the "deleted-test map" the readiness review (#260) asked #286 to check in; every open gap row links the issue that closes it.

Regenerate the file list with:

```
git diff --name-status --diff-filter=D 504846c 8dccc74 -- tests/ test/
```

Both ends are pinned on purpose: `origin/2.x.x` has moved past 504846c and adds test files of its own, and this branch removes eight `test/test-prism-*.sh` wrappers on its own; neither is a cutover deletion and neither is a row here.

The same pinned deletion set is checked in as [prism-deleted-test-files.txt](prism-deleted-test-files.txt), with its generation command in the header. The offline check compares file-row names against this manifest, so it also works in shallow checkouts without either historical commit.

The 17 case rows under `tests/test_prism_pending_block_recovery.py` are checked against [prism-deleted-test-cases.txt](prism-deleted-test-cases.txt), generated from that file's test methods at the same pinned 2.x.x revision. This separate inventory keeps individual cases from disappearing or being renamed while the file counts still match.

How the rows were derived: each 2.x.x file was read at 504846c (module docstring, test names, test bodies by behaviour cluster), then the native suites were searched and read: `crates/qbit-prism-server/tests/*.rs` (with `support/` and `observability/`), `#[cfg(test)]` modules under `crates/qbit-prism-server/src/`, `crates/qbit-prism/tests/*.rs`, `crates/qbit-prism/src/`, and the Python tests that remain under `tests/`. A native test is cited only where its body asserts the behaviour. Many cited native tests are gated on `PRISM_TEST_DATABASE_URL`, `PRISM_TEST_PG_BIN_DIR` or `QBITD_BIN`; they take those inputs through the shared gate described in [prism-integration-test-gate.md](prism-integration-test-gate.md), and the `prism-native-postgres` job proves from the gate's manifest that each of them executed. The nine PostgreSQL-gated decision-D2 coordinator tests from #316 (`crates/qbit-prism-server/src/coordinator/d2_bootstrap_tests.rs` and `d2_below_target_tests.rs`) are cited where they assert a deleted test's behaviour or its documented 3.x.x replacement rule (`docs/prism-rust-migration.md`, "Payout differences from 2.x.x (decision D2)").

Status values:

- **full**: every behaviour the 2.x.x file asserted has a named 3.x.x test.
- **partial**: some behaviours have a native test; the row names what is not covered, and links the issue when one covers the remainder. Sub-behaviours whose subject no longer exists are marked retired inside the row. A partial row with no "not covered" clause has nothing left uncovered: everything it does not cite is retired, and it is partial rather than full only because of that.
- **open gap**: no native test; the linked issue closes the gap.
- **needs triage**: no native test and no issue that closes it, or the mapping is unclear.
- **retired**: the subject no longer exists in 3.x.x (Python-runtime mechanics with no native counterpart); neither a gap nor a replacement.

In the replacement column `path::name` is a Rust test function (`#[test]` or `#[tokio::test]`) or a remaining Python `def test_`, with `path` relative to the repository root. A test that a macro generates has no `fn` line of its own, so it is named in prose beside its file, not as `path::name`.

Issues are named in two ways, and the difference is checked (see [Keeping this map current](#keeping-this-map-current)). A link, written `→ [#N](…)` where it owns a remainder, names an **open** issue the row depends on: the issue that owns behaviour no native test covers, or one the row's reason leans on. A plain `#N` is history: the closed issue or merged pull request the cited tests came from, or the issue that closed without a behaviour. A closed issue is never the owner of an uncovered behaviour.

## Keeping this map current

This map is evidence for the cutover go/no-go (#291), so it is checked, not trusted. The rule the checks serve: **the pull request that closes an issue this map links updates the map in the same change.** Name the tests that landed and move the row to full or partial; retire what has no native subject, with the reason; and where behaviour is still uncovered, link an open issue whose body names it, or write "not covered, no open issue".

`python3 scripts/check_deleted_test_map.py` runs in the required `Lint, compile, and Compose validation` job, offline, and fails when:

- a deleted file from the pinned manifest has no file row, a file row names a file outside that manifest, or the manifest is unreadable, empty or contains duplicates;
- a case from the pinned case manifest has no case row, a case row names a case outside that manifest, or the case manifest is unreadable, empty or contains duplicates;
- a `path::name` reference names a file that is not in the repository, a function that is not in that file, or a function that is not a test;
- a table line does not parse, a status is not one the legend defines, a row's text does not lead with its status, a full or partial row cites no test, or an open gap row links no issue;
- the summary table or the section row counts differ from the rows, or the needs triage index differs from the needs triage rows;
- an issue link does not point at this repository's issue of the same number, or an owner arrow is followed by a bare `#N` instead of a link.

`python3 scripts/check_deleted_test_map.py --check-issues` also asks GitHub for the state of every issue the map depends on (any issue link inside a table row, and any `→` link anywhere) and fails when one is closed. It runs as the `deleted-test-map-owner-issues` job on every pull request and every push to `3.x.x`. That job is deliberately not required: an issue closing must not block an unrelated pull request. A red run there is the prompt to reconcile the row it names. It exits 2, not 0, when GitHub cannot be asked (network, rate limit, unexpected reply): an unknown state is never read as open. The job rides on CI and not on a schedule because a `schedule` or `workflow_dispatch` trigger only fires from the default branch, and this map lives on `3.x.x`; run the whole workflow by hand with `gh workflow run ci.yml --ref 3.x.x`, or the check alone with `GH_TOKEN="$(gh auth token)" python3 scripts/check_deleted_test_map.py --check-issues`.

`python3 scripts/check_deleted_test_map.py --summary` prints the row counts and the rows that are still open, which is what a sign-off comment on #291 should quote.

What the checks cannot see: whether a cited test's body still asserts what the row says, and an ownership claim written as a plain `#N`. Both are review's job, which is why a plain `#N` must only ever be history.

## Native storm evidence

The #270 tests exercise the native lifecycle rather than the retired selector.
The four cleanup tests in
`crates/qbit-prism-server/src/ledger/candidates/storm_fault_tests.rs` use small
populations with neighbouring rows to check fault isolation:

- `a_failed_or_shifting_chain_observation_leaves_the_drain_recoverable`: failed
  or incoherent chain observation retains offer metadata and permits recovery.
- `a_lost_landing_acknowledgement_rolls_back_and_the_next_attempt_lands`: a lost
  write acknowledgement rolls back the landing; recovery does not resubmit.
- `a_lost_terminal_commit_acknowledgement_stays_terminal`: a committed terminal
  outcome survives its lost acknowledgement and cannot be claimed again.
- `a_lost_renewal_acknowledgement_cancels_only_that_attempt`: failed renewal
  cancels the pre-offer attempt; the next legal attempt submits exactly once.

The provenance tests in
`crates/qbit-prism-server/src/coordinator/storm_evidence_tests.rs` distinguish
row state and ownership from an actual counted node call:

- `a_pre_offer_retry_records_no_call_and_leaves_the_row_pending`
- `a_held_and_renewed_lease_before_any_call_is_not_offer_evidence`
- `a_pre_offer_supersession_terminalizes_without_any_call`
- `a_replay_adoption_after_restart_records_an_unknown_offer_with_no_call`
- `offer_path_records_a_counted_call_with_a_durable_timestamp_and_reply`
- `a_known_call_keeps_its_call_evidence_through_orphan_terminalization`
- `an_interrupted_reservation_orphans_unknown_without_inventing_a_call`

The supersession case does not exercise the old capacity-closed selector
condition: there is no equivalent native condition. Replay adoption uses a
second frontend after claim expiry; the separate restart integration test kills
a real process. An interrupted reservation may terminalize as `orphaned` with
an unknown outcome and no call timestamp or reply. These small-population cases
do not claim a 3,120-candidate repetition of each fault, per-height chain-probe
deduplication, post-restart SQL statement-cost measurement, or exhaustive failure
injection at every chain RPC.
